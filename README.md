## Android 15 新限制

请注意，Android 15 新系统，对app权限进一步限制，需要打开usb调试模式，使用adb执行shell命令：

```
appops set com.vone.qrcode RECEIVE_SENSITIVE_NOTIFICATIONS allow
```

手动授予 `RECEIVE_SENSITIVE_NOTIFICATIONS`  权限，才能正常监听某些 支付宝 消息，否则会导致漏单等情况。这是Android15 新加入的限制，目前没有其他办法绕过

> 部分消息会被系统拦截，部分消息能够正常监听，这是新系统的默认行为，并非软件无法监听。手动授予权限后，才能监听到完整的通知消息
> Android 14 以及低版本没有这个限制

## 简介

此处为fork自原作者的修改版
主要修改增加几项功能：

1. 支持开机自启(国内定制系统需手动开启自启权限)
2. 支持post失败后再重试一次(这次重试是强制亮屏的)
4. 支持 v2 HMAC-SHA-256 签名校验与防重放时间戳窗口
5. 集成 Material You 风格状态卡片与实时诊断能力
6. **支持服务端 HTTPS 配置（含自签证书）**：手动输入 `https://` 前缀或扫 `https://host/key` 二维码即走 https，默认 http 兼容老配置（v3.1.3）
7. **修复启动必崩**：v31 主题 windowBackground 用 `<bitmap>` 包 VectorDrawable 导致 Android 12+ 启动闪退（v3.1.1）
8. **微信 / 支付宝存活监控**：按间隔周期检查两个应用是否还在运行；有 Shizuku 时用 `pidof` 精确判断，没有则降级为「使用情况访问」推断，两者都缺时明确显示「无法检测」而不是谎报「未运行」（v3.3.2）
9. **统一运行日志**：内存 + 按天滚动文件（保留 3 天），重启后仍可回看；心跳、保活、存活检测、日志管理全部留痕，日志内容脱敏（配置页除外），支持导出与清除（v3.3.2）

优化功能：

1. 优化了里面大量的 okhttp 的访问，做成了单例,防止某些情况下可能导致的内存溢出、错误崩溃等等
2. 增加了一次网络重试（没有做三次、四次是防止重复提交导致订单出问题），而且是唤起到前台的网络重试，（之所以唤起到前台，是测试过小米等机型，如果app长时间在后台（6小时以上），app会被限制网络，除非启动前台Service或者Activity

修改版特点：可以装在自己的日用安卓机器上，不用专门找一台机器亮屏挂机了。因为修改版支持错误重试，如果装在日用机器上推送失败，软件会强制打开一个前台Service以及一个前台Activity

前台页面的打开需要手动开启两项权限：后台弹出页面、锁屏显示

> 在使用过程中，可以将屏幕关闭，省电，然后在收到支付信息后，软件会自动的打开前台并推送支付信息。
> 软件里面的心跳本来想移除用来省电的，但基于可靠性，虽然心跳会略微增加耗电，但还是没有去除

## 安装

 + 下载服务端程序，可选PHP/Java版，按照说明安装
 + 下载编译好的Apk,安装后扫码/手动配置 即可使用

 > 升级说明：请您直接下载新版本覆盖旧版本即可！

### HTTPS 配置（v3.1.3 起）

- 手动配置：地址栏直接输入 `https://你的域名:端口`（带前缀会自动记住协议）；不带前缀沿用已保存的协议
- 扫码配置：服务端二维码格式为 `https://host/key` 即可走 https；裸 `host/key` 默认 http
- 客户端默认信任自签证书（个人部署场景）；**v3.1.4 起可在配置卡打开「验证服务器证书」开关**，走系统 CA 严格校验——服务端使用正式证书（Let's Encrypt 等）时建议开启

### 从旧版本（v2.x / V3.1 之前）升级到 v3.1.3

> ⚠️ v3.1.3 起改用全新自签签名（vmqfox.keystore），与旧版作者签名不同，**无法覆盖安装**：
> 必须先卸载旧版再安装，并重新配置服务端地址、重新授予通知使用权与 `appops` 授权。

## 说明
 + 请部署完成后访问后台，有详细的Api说明

 + **存活监控怎么用**（v3.3.2 起，v3.3.4 增强）：设置页 →「微信 / 支付宝 存活监控」
     + 有 Root：点「检测 Root」授权后，用 `su` 执行 `pidof`，结果精确（`运行中（pid=xxx）`）
     + 有 Shizuku：授权后同样精确，但 Shizuku 自己被杀就失效
     + 两者都没有：点「授予使用情况访问权限」跳到系统页面手动打开，此时只能判断「最近活跃」，**不代表进程存活**
     + 都没有授权：显示「无法检测」，这是**权限缺失**，不是微信/支付宝没运行
     + 任何情况下都不会把「不知道」显示成「未运行」
     + 开启「未运行时自动拉起」后，被杀的微信/支付宝会被自动拉回来（10 分钟冷却 / 每小时最多 6 次）

 + **不用的时候怎么省电**（v3.3.4，v3.3.5 加固）：主页右上角总开关，或设置页「运行控制」
     + 关掉「通知监听」→ 不再解析任何通知；关掉「心跳上报」→ 不再发心跳、不再唤醒前台
     + 两个都关 → 保活循环一起停，线程挂起休眠（不占 CPU、不产生唤醒）
     + **进程不会被杀、监听服务不会断**，重新打开立刻恢复，不用重启 App
     + 挂起最多 5 分钟会自行醒来复查一次状态（安全阀）。这个定时器在设备休眠时不被服务，**不会把手机唤醒**，
       它的作用是保证任何「改了开关却没通知」的写法都不会让线程永久挂死

 + **日志在哪看**（v3.3.2）：设置页 →「运行日志」，可切换级别、导出、清除
     + 文件路径：应用私有目录 `files/logs/vmq-yyyy-MM-dd.log`，按天滚动，保留 3 天
     + 日志已脱敏（IP/域名/密钥/URL 参数/通知原文），但**配置页展示的 host 与 key 是原值**，方便核对
